Service-impacting — automated job-discovery pipeline returning 0 results for all categories all day

Summary

Sonar’s web-search step is no longer feeding search results to the language model for our API calls today (2026-05-01). The model receives an empty
<search_results>
block (or “None”) and correctly responds with
[]
. This was visible in
sonar-pro
only as
completion_tokens=1
and an empty content body, but became fully diagnosable when we swapped to
sonar-reasoning-pro
, which exposed
<think>
traces in which the model itself states:
“the search_results section is empty/None… There are NO search results provided.”

The issue affects 3 of 4 of our prompt categories with
searchResults=0
and 1 category with
searchResults=1
(returning a single irrelevant URL:
https://mmwlegal.com/author/mmwmmwlegal-com/
). The same prompts and configuration worked normally earlier this morning (6:22 AM CDT) — at least for one of the four categories.

We suspect either an account-level search degradation or a broader Sonar search-pipeline incident not currently reflected on
status.perplexity.com
.

Reproducer

POST https://api.perplexity.ai/chat/completions
with body:

{
"model": "sonar-pro",
"messages": [
{ "role": "system", "content": "You are a thorough job-search assistant. Search multiple job boards (LinkedIn, Indeed, BuiltIn, company career sites) and return real currently-live postings that match the user's criteria. Return ONLY a valid JSON array of job objects — no commentary, no markdown fences, no prose outside the JSON. Only the 5 REQUIRED fields are mandatory; for OPTIONAL fields, return \"\" (empty string) when unknown rather than dropping the posting. Prefer returning 1–3 imperfect-but-real matches over returning []. Only return [] if you genuinely cannot find anything after searching." },
{ "role": "user", "content": "Find Asset-Based Lending (ABL) analyst-level positions in the United States across THREE title families... [full prompt available on request — ~1600 prompt tokens of named-employer anchors and title-phrase enumerations]" }
],
"temperature": 0.3,
"search_recency_filter": "month",
"web_search_options": { "search_context_size": "medium" }
}

The reasoning model’s
<think>
traces are the smoking gun.
Verbatim excerpts from
choices[0].message.content
(first ~500 chars):

ABL:

<think>
The user is asking me to search for ABL (Asset-Based Lending) analyst-level positions in the United States across three title families. However, looking at the search results provided, I see:

<search_results>

Search results:

None

</search_results>

There are NO search results provided. The search_results section is empty/None.

SF:

<think>
...However, I've been given search results that are empty (no search results provided). The instruction says "None" under search_results.

FPA:

<think>
...the "search results" provided to me are from a law firm website (mmwlegal.com) discussing legal topics like company directors, shareholder disputes, surrogacy, and insolvency. These search results are completely irrelevant to the FP&A job search request.

IBR:

<think>
...The search results provided are "None" - so I need to conduct a search myself.
However, I'm an AI assistant and I don't have the ability to browse the internet in real-time, access LinkedIn, Indeed, Builtin, company career sites, or any other live job boards.

The model is explicitly stating it received no search results. This points to the search-retrieval step of Sonar — not the language-model step — being the failing component.

Things we ruled out on our side

Prompt content
— IBR’s prompt was unchanged across runs 1–5; it worked in run 1 and broke in runs 2–5.

Temperature
— tested 0, 0.2, 0.3 with same result.

max_tokens
— tested with and without an explicit 4000-token budget.

search_context_size
— tested both
medium
and
high
.

Model
— tested both
sonar-pro
and
sonar-reasoning-pro
.

search_recency_filter
— kept at
"month"
throughout; not changed.

API key / auth
— all responses returned
status=200
with no auth or rate-limit errors.

Account/billing
— no plan changes today.

Things we suspect are on Perplexity’s side

Search retrieval pipeline returning empty results to the LLM.
The reasoning-model
<think>
traces directly evidence this.

The recurring
mmwlegal.com/author/mmwmmwlegal-com/
citation
appearing in 3 of 5 runs across different prompts is suspicious — looks like a stale cache hit or a bug where one fixture leaks into unrelated queries.

The status page (
status.perplexity.com
) shows no incidents, but the historical pattern of
sonar-pro
runs returning empty all week (per our cron history) suggests this may be a slow degradation rather than an acute outage.

Request

Investigate whether the search-retrieval step of Sonar is failing to populate
<search_results>
for our account on
sonar-pro
and
sonar-reasoning-pro
.

Confirm whether other accounts are seeing the same pattern.

Advise whether there is a workaround we can apply on the request side (different parameter combination, different model, etc.) that would re-engage the search step.

Happy to enable additional verbose logging or share full request/response payloads for any of the 16+ failed calls captured today.
